# Request Management

## Purpose

Request Management handles work that someone wants done.

Unlike incidents, nothing is broken.

The goal is to provide a service, access, information, or a routine change in a controlled and trackable way.

Examples:

- Software installation
- Password reset
- Access request
- Equipment request
- Shared folder access
- VPN access
- New user setup
- Information request

Simple rule:

> A request is something someone needs.
>
> An incident is something that stopped working.

---

# How To Identify A Request

Ask:

## Is Something Broken?

If YES

→ Incident

If NO

→ Request

Examples:

### Request

User needs VPN access.

Nothing is broken.

Work needed:
- Verify approval
- Grant access
- Confirm working

---

### Incident

User had VPN access yesterday but cannot connect today.

Something stopped working.

Work needed:
- Investigate cause
- Restore service

# Common Request Types

## Access Requests

Examples:

- VPN access
- Shared drive access
- Email group membership
- Application permissions

Typical checks:

- Approval received
- Correct user
- Correct access level

---

## Software Requests

Examples:

- Application installation
- Software upgrade
- License assignment

Typical checks:

- Business need
- Compatibility
- Licensing requirements

---

## Hardware Requests

Examples:

- Laptop
- Monitor
- Keyboard
- Replacement equipment

Typical checks:

- Availability
- Asset assignment
- Delivery process

---

## Account Requests

Examples:

- New account creation
- Password reset
- Account unlock

Typical checks:

- Identity verification
- Approval requirements

---

## Information Requests

Examples:

- System details
- Network information
- Asset information
- Status updates

Typical checks:

- Verify requester
- Verify information can be shared

---

# Request Workflow

```text
Request Received
       ↓
Review Request
       ↓
Verify Requirements
       ↓
Perform Work
       ↓
Confirm Completion
       ↓
Close Request
``
